# 文献快下

文献快下是一个本地运行的小型图形界面工具：后端使用 Python，界面使用 HTML/CSS/JavaScript，通过浏览器打开本机地址 `127.0.0.1`。它不是命令行程序，也不依赖云端服务；程序和下载结果都保存在本机。

## 主要功能

- 从 `.xlsx`、`.csv`、`.tsv` 或每行一个 DOI 的 `.txt` 导入文献清单。
- 页面保持打开时可以连续上传多个文件；每次上传会建立独立批次，不覆盖之前的批次。
- 通过论文行前的复选框、全部勾选/取消或“起始序号—结束序号”选择本次要处理的文献。
- 直接在页面输入一个或多个 DOI，不必为了单篇文献制作 Excel。
- 自动读取 Excel 中的中文标题、英文标题、Title 等列；缺失标题时可单独点击“一键获取标题”。
- 获取标题期间仍可调整勾选范围；标题查询和下载启动彼此独立。
- 自动查询 DOI、Europe PMC、Crossref、OpenAlex、Semantic Scholar 和论文落地页，下载可公开获取的 PDF。
- 自动检查 PDF 是否可打开，并在清单中记录 DOI 匹配、标题匹配或未匹配结果。
- 对需要机构访问的论文，最后统一打开浏览器处理；用户可以手动完成华中科技大学等机构的授权登录，再让程序接收下载结果。
- 支持随时暂停、继续、结束批次、重试、PDF 预览和 Excel 下载清单导出；标题查询可以和自动下载并行。
- 人工处理会记录为“人工待处理 / 人工处理中 / 人工处理完成”，即使取消勾选也不会丢失状态；页面不显示绝对本机路径。
- 页面分为“待处理”和“已完成”两个视图。只要接收到有效 PDF 就会进入“已完成”；即使 DOI/标题没有匹配，也会在清单中保留未匹配结果，不再单独进入核验队列。未找到 PDF 或需要机构访问的条目继续留在“待处理”。手动在外部下载后，点击该行“标记已完成”即可移动；这种手动确认会明确标记为未由程序校验。首次点击会提醒一次，确认后同一浏览器不再重复提醒。
- 每篇论文的“下载入口”会折叠显示多个候选链接，包括 DOI/出版社页面、输入表中的链接、程序发现的 PDF 或开放获取入口，以及 Europe PMC、Semantic Scholar 和 Google Scholar 检索入口；这些入口只是备用来源，不代表每个链接都一定有全文。
- 页面可以选择新建批次的保存文件夹，也可以打开当前保存文件夹；具体绝对路径不显示在网页中。已有批次不会因修改设置而迁移。
- 浏览器登录会话与下载批次分开保存，不会写回原始工作簿或项目审核库。

页面端使用匿名批次编号，不显示用户上传文件名、用户名、本机项目路径或文件位置。

程序不会绕过验证码、密码、多因素认证或出版社的访问控制。机构阶段需要用户在自己有权限的浏览器会话中完成操作。

## 本机快速启动

在文件管理器中运行 `启动文献快下.sh`。启动脚本会把服务放到后台运行，并使用固定的本机地址 `http://127.0.0.1:43127/`，因此关闭启动终端或页面空闲不会停止上传服务；页面打开后可反复上传文件或添加手动 DOI。页面刷新、服务短暂重启后，网页会自动重连。只有点击页面右上角“停止并退出”才会停止本地服务。若服务发生未预期异常，启动脚本会自动重启：

1. `PAPERFETCH_PYTHON` 指定的 Python；
2. 项目目录下的 `.venv/bin/python`；
3. 系统 `python3`。

如果系统 Python 尚未安装依赖，在项目目录中执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

随后再次运行启动脚本。机构阶段需要本机可用的 Google Chrome 或 Chromium；程序会优先使用 `/usr/bin/google-chrome`。

## 构建本地可执行版本

Ubuntu 可以在本机运行 `构建Ubuntu版本.sh`，它会使用当前 Python 环境构建 `dist/PaperFetch`；构建完成后运行 `安装Ubuntu可执行版.sh`，即可在应用菜单看到“文献快下”。构建依赖只用于打包，不会改变运行数据目录。

如果程序位于外置 NTFS 磁盘，直接双击可执行文件可能被挂载权限拦截。推荐生成并安装标准 Debian 包：先运行 `构建Ubuntu安装包.sh`，然后执行 `sudo apt install ./dist/paperfetch_1.1.1_amd64.deb`。也可以运行 `打包Ubuntu便携版.sh`，把生成的 `PaperFetch-Ubuntu-amd64.tar.gz` 解压到本机 home 目录，再运行其中的 `启动Ubuntu便携版.sh`。

Windows 的 `.exe` 必须在 Windows 环境构建，不能用 Ubuntu 的 PyInstaller 直接交叉生成。将项目复制到 Windows 后，在 PowerShell 中运行 `literature_downloader\\build_windows_release.ps1`，会生成 `dist\\PaperFetch\\PaperFetch.exe` 及 `_internal` 依赖目录；也可以把项目发布到 GitHub 后，由 Actions 自动构建。最终用户只需要解压完整的 Windows ZIP 并双击 `PaperFetch.exe`，不需要 Python 或 BAT 文件；Actions 会自动执行 Windows 冒烟测试并打包目录版发布物。

冻结后的版本会把数据库、PDF 和设置保存到系统用户应用数据目录：Ubuntu 通常为 `~/.local/share/paperfetch/`，Windows 通常为 `%LOCALAPPDATA%\\PaperFetch\\`。页面仍不会显示这些绝对路径。机构访问阶段会优先使用已安装的 Chrome、Edge 或 Chromium；如果电脑没有可用浏览器，需要先安装其中一种，或设置 `PAPERFETCH_BROWSER_EXECUTABLE`。

## 安装桌面图标

运行 `安装桌面启动器.sh`，它会把启动项安装到当前用户的应用菜单，并安装配套的 SVG 图标。安装脚本会根据当前克隆目录生成路径，因此把项目放到 GitHub、换到其他目录后仍然可以使用。

安装后可直接从系统应用菜单启动；如果不安装桌面项，也可以随时运行同目录的 `启动文献快下.sh`。

## 数据与隐私

运行数据默认在 `data/` 下；也可以在页面“文献保存位置”中为新批次选择其他本机文件夹。数据库、批次 PDF 和锁文件均被 `.gitignore` 排除，不应提交到公开仓库。机构浏览器配置默认在用户目录的 `.local/share/paperfetch/browser-profile/`，其中可能含登录状态，不能分享或提交到 GitHub。

页面中的批次名称使用匿名批次编号，不显示上传文件名、用户名、下载目录或项目绝对路径。导出的下载清单仍会包含本机保存路径，这是为了便于你在本机定位文件；该清单不要上传到公开仓库。

自动下载成功率取决于文章是否开放获取、出版社是否提供稳定 PDF 链接、网络响应以及学校授权。程序现在增加了 OpenAlex、Semantic Scholar、Crossref PDF link、Europe PMC 和出版商页面元标签/链接等通道，但不会绕过付费墙、验证码或机构认证；因此仍可能有文章需要人工完成。

## 共享到 GitHub

建议只提交本目录中的源代码、`README.md`、`requirements.txt`、启动脚本和 `assets/`，不要提交 `data/` 里的数据库、下载文件或浏览器配置。仓库可以设为私有或公开；如要公开发布，建议再根据你的课题组要求补充许可证和版本说明。
