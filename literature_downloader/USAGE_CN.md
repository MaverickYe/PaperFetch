# 文献快下

这是供本机使用的中文图形界面。在文件管理器中运行 `启动文献快下.sh`，浏览器将自动显示操作页面；也可以先运行 `安装桌面启动器.sh`，以后从系统应用菜单点击“文献快下”。启动脚本会把服务放到后台运行，使用固定地址 `http://127.0.0.1:43127/`，页面保持打开时可以反复上传文件或添加 DOI，长时间不操作也不会因启动终端关闭而停止。服务异常退出时会自动重启，网页会自动重连。只有点击页面右上方“停止并退出”才会停止本地服务；停止后重新打开应用入口即可继续使用。界面只监听本机地址。

本目录可以整体复制或提交到 GitHub 共享。首次换电脑时，先按 `README.md` 安装 Python 依赖；不要提交 `data/` 中的数据库和 PDF，也不要提交浏览器配置目录。

1. 选择 `.xlsx`、`.csv`、`.tsv` 文件，表中使用名为 `DOI` 的列；也可选择每行一个 DOI 的 UTF-8 `.txt`。Excel 会识别包含 DOI 的工作表；表中已有的 PDF URL、论文页面等也会参与查询。去重按 DOI 忽略大小写；重复和无效条数显示在导入提示中。
2. 如果只需要部分文献，使用论文列表中的复选框；也可以点击“全部勾选”“全部取消”，或输入 1-based 起止序号后点击“选中范围”。只有已勾选且处于等待状态的条目会进入自动下载。
3. 表格若包含 `中文标题`、`英文标题`、`Title`、`论文标题` 等列，标题会直接显示；缺少标题时点击“一键获取标题”，程序会查询 Europe PMC、Crossref、OpenAlex、Semantic Scholar、DOI 论文页面以及页面中的 PDF 元标签/链接。标题查询可以与自动下载同时运行。也可以在“手动输入 DOI”框中粘贴一个或多个 DOI，点击“添加为新批次”，无需制作 Excel。
4. 点击“文献保存位置”中的“选择文件夹”，为以后新建的批次选择保存目录；“打开保存文件夹”可以直接打开当前目录，“恢复默认”回到应用数据目录。页面不显示绝对路径，已有批次不会迁移。
5. 点击“开始自动下载”。程序先用多个开放获取和出版商通道查找 PDF；最多三个论文同时处理，同一主机的请求有间隔。点击“暂停下载”可暂停，之后点击“继续下载”恢复；点击“结束批次”会结束本批次并保留已完成文件和未完成列表。网络、出版社响应和授权范围会影响成功率。
6. 页面上方有“待处理”和“已完成”两个视图。只要接收到有效 PDF，文章就会自动进入“已完成”；即使 DOI/标题没有匹配，也会保留未匹配结果但不再进入单独的核验队列。没有找到全文或需要机构访问的文章继续留在“待处理”。
7. 每篇文章的“下载入口”可以展开查看多个候选页面或 PDF 直链，包括 DOI、出版社、输入表链接、开放获取来源，以及 Europe PMC、Semantic Scholar 和 Google Scholar 检索入口；某个站点打不开时，可以尝试其他入口。
8. 自动阶段结束后，点击“开始机构访问处理”。Chrome 会打开独立的自动化浏览器配置，供你进行机构登录；每篇文章打开后程序会尝试识别并点击 PDF。登录时可使用“尝试选择华中科技大学”，回到文章后可使用“尝试点击 PDF”。遇到不同的登录页面、验证码、二次认证、PDF 阅读器等情况，直接在新窗口操作。接收到 PDF 后程序会验证，验证通过即自动进入“已完成”。如果你在浏览器或其他工具中手动完成下载，点击该行“标记已完成”，它会从待处理列表移入已完成列表；程序会记录这是“手动确认”，但不会声称已校验文件。首次点击会提醒一次，确认后同一浏览器不再重复提醒。
9. 论文行可点击“查看 PDF”；点击“导出下载清单”，得到含下载清单和处理日志的 Excel，包含每篇 DOI、状态、页面、保存路径、SHA-256、匹配情况和手动下载入口。每批的 `pdf/` 保存所有接收到的有效 PDF；清单中的“身份校验”仍会标出 DOI 一致、标题匹配或未匹配，但不再阻止下载归档。

10. 页面右上角可以切换“浅色模式 / 深色模式”，选择会保存在当前浏览器，下次打开页面会沿用。浅色模式使用白色主色调，深色模式使用炭黑和蓝色强调。

## 生成本地软件

Ubuntu：运行 `构建Ubuntu版本.sh` 生成可执行文件，再运行 `安装Ubuntu可执行版.sh` 安装应用菜单图标。Windows：在 Windows 上运行 `build_windows_release.ps1`，生成 `dist\\PaperFetch\\PaperFetch.exe` 及 `_internal` 依赖目录；也可以使用 GitHub Actions 的 `Build Windows executable` 工作流自动构建 Windows ZIP。最终用户解压完整 ZIP 后直接双击 `PaperFetch.exe`，不需要 Python 或 BAT 文件。Ubuntu 不能直接用 PyInstaller 生成 Windows `.exe`，因为 PyInstaller 需要在目标操作系统上打包。

如果项目放在外置 NTFS 磁盘，直接运行二进制文件可能被挂载权限阻止。Ubuntu 更标准的方式是运行 `构建Ubuntu安装包.sh` 生成 `.deb`，再执行 `sudo apt install ./dist/paperfetch_1.1.1_amd64.deb`；或者运行 `打包Ubuntu便携版.sh` 生成 `.tar.gz`，解压到 home 目录后运行 `启动Ubuntu便携版.sh`。

批次和数据库默认位于 `literature_downloader/data/`；选择自定义保存目录后，新批次的原始输入和 PDF 会放到所选目录下。输入表及 PDF 保留原件，程序不会写入其他项目工作簿或审核库。浏览器会话位于 Ubuntu 本地 `~/.local/share/paperfetch/browser-profile/`，其中可能含登录状态，请勿分享或提交到公开仓库。程序不读取平时 Chrome 的用户配置、不要求输入密码。日志和清单中的网络地址会去掉查询参数，避免保存临时令牌，因此部分需要查询参数的来源地址可能无法直接复现。

依赖使用 Python 3.12 环境安装：`requests`、`openpyxl`、`pymupdf` 和 `playwright`，机构阶段使用本机的 Chrome、Chromium 或 Edge。程序没有自动破解访问控制、验证码或超出机构授权下载的功能；应遵守学校与出版社的访问和使用条款。
